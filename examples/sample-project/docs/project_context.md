# PROJECT_CONTEXT — Weekend Trip Plan

> Read-only example. Fictional project, filled in to show what a finished context file looks like.

## Vision
A simple, low-stress plan for a two-day weekend trip within driving distance — something you could glance at once and just follow.

## Principles
- Keep it to one page. If it doesn't fit, it's too much trip.
- One anchor activity per day, not a packed schedule.
- Plan for the trip going slightly wrong, not perfectly.

## Current Goal
Produce a one-page plan: where to go, where to stay, one anchor activity per day, and a rough budget that includes getting there.

## Current Phase
Done.

## Key Decisions
- Scoped to a single weekend within driving distance to keep the first plan simple.
- Chose one anchor activity per day over a full itinerary.
- Included a rain backup for the outdoor day.

## Assumptions
- Two people, own car, leaving Saturday morning and back Sunday evening.
- Budget is a soft cap, not a hard limit.

## Constraints
- Driving distance only (no flights).
- Must fit on one page.

## Open Questions
- None remaining — plan was finalized after review.

## Key Lessons (Max 10)
1. The first draft of any plan tends to leave out the boring costs (travel, parking) — check for missing line items.
2. A single anchor activity per day reads as relaxing; three reads as a chore.
3. Asking "what if it rains / it's closed / we're late" up front is cheaper than rescuing the day later.
