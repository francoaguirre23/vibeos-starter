# STANCE Instructions

## Purpose
Maintain STANCE.md as the real-time log of decisions, heuristics, constraints,
mistakes, and preferences within this project.
STANCE is the raw material that feeds project SIGNALS.

## Use This When
- After writing code or making a meaningful decision
- After debugging or resolving a conflict between personas
- Before committing major changes
- At the end of BUILD / VALIDATE / REVIEW phases

## Inputs
- Current work context (code, decisions, changes, persona outputs)

## Required Output
Append high-signal entries to the project STANCE.md.

---

## What to Capture

Only include:

- [Decision] → what was chosen and why
- [Heuristic] → a working rule used in this project
- [Constraint] → a limitation affecting decisions
- [Mistake] → what went wrong and how it was corrected
- [Conflict] → disagreement between personas and how it was resolved
- [Preference] → observed behavioral tendency

---

## Entry Format

- ≤3 lines per entry
- One idea per entry
- Include short reasoning if possible
- Tag the source: [self] or [persona-name]

Example:

[Decision][self] Used a script over a UI → faster to ship, no UI needed yet
[Heuristic][sam] Prefer read-only first → reduces risk early
[Mistake][self] Built before clarifying inputs → added explicit input examples
[Conflict][robin] Unclear data shape flagged in review →
  resolved by writing down the contract before building

---

## Rules

- Append only — do not edit or delete past entries
- Avoid duplication unless marking recurrence
- Keep entries concise and high-signal
- Every major cross-persona decision must have a STANCE entry

---

## Recurring Pattern Detection

If an entry:
- appears multiple times in this project
- is not tool-specific

→ mark it with [Recurring]
→ eligible for project SIGNALS.md

---

## What NOT to Include

- Long explanations
- Temporary or trivial notes
- Tool-specific implementation details
- Anything that does not affect decision-making
