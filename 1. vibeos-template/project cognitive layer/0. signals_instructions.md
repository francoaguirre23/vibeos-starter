# SIGNALS Instructions

## Purpose
Maintain project SIGNALS.md as the staging layer between raw STANCE entries
and the project MINDSET. SIGNALS captures recurring patterns from this project
that are candidates for distillation into the project MINDSET — and eventually
the Global MINDSET.

## Use This When
- End of a meaningful work session
- After multiple STANCE entries accumulate
- When something feels like it's happening more than once
- Before closing out a project phase

## Inputs
- Project STANCE.md (look for [Recurring] entries and strong patterns)

## Required Output
Append high-signal patterns to project SIGNALS.md.

---

## What to Capture

Only include patterns that are:
- Recurring (appear ≥2 times in STANCE) or strongly felt after one instance
- Not tool-specific or one-off
- Generalizable beyond the immediate context

---

## Entry Format

Pattern:
<short distilled statement>

Type:
Heuristic / Anti-pattern / Preference / Risk pattern

Source:
[self] = builder decision | [persona-name] = persona recommendation

Evidence:
- <project/context> — <1 line>
- <project/context> — <1 line>

Confidence:
Low / Medium / High

Scope:
Project-specific / Likely general / Clearly general

---

## Rules

- Do not include one-off observations unless confidence is very high
- Do not include implementation details
- Append only — do not edit past entries
- Avoid duplicates
- Keep entries concise

---

## Promotion Criteria → Project MINDSET

Eligible for project MINDSET if:
- Confidence = Medium or High
- Pattern appeared ≥2 times in this project OR once with high confidence
- Represents a decision-making or design pattern, not an outcome

---

## What NOT to Include

- Raw STANCE log entries
- Tool-specific behavior
- Temporary constraints that only apply to one task
