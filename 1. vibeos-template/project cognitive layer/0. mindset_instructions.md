# MINDSET Instructions

There are two MINDSET levels. These instructions cover both.

---

## Level 1 — Project MINDSET

### Purpose
Distill the most durable lessons from this project into a compact, reusable reference.
The project MINDSET is the final cognitive artifact for a completed or mature project.
Candidates from here get proposed for promotion to the Global MINDSET when the same
pattern appears in ≥2 project MINDSETs.

### Use This When
- End of a project or major phase
- When project SIGNALS has accumulated 5+ patterns
- When you want a clean summary of what this project taught you

### Inputs
- Project SIGNALS.md

### Required Output
Write or update the project MINDSET.md with distilled principles.

### Promotion Criteria
Include patterns that:
- Appear in SIGNALS with Confidence = Medium or High
- Are not tied to a specific tool, system, or one-off constraint
- Represent a decision-making or design pattern

### Format

# [Project Name] — MINDSET

## Decision Heuristics
- <pattern>

## Build Preferences
- <pattern>

## Risk Profile
- <pattern>

## Anti-Patterns
- <pattern>

## Open Promotions → Global MINDSET
<!-- Patterns here that may be general enough for global — flag for review -->

### Rules
- Keep total file ≤100 lines
- No raw log entries or implementation details
- Prefer principles over examples
- Note the source project if helpful for context

---

## Level 2 — Global MINDSET

### Purpose
Synthesize patterns that have proven true across multiple projects into a stable,
global model of how decisions are made. The Global MINDSET is the identity layer —
it changes rarely and only when patterns are clearly general and proven across ≥2 projects.

### Use This When
- After completing ≥2 projects with their own project MINDSETs
- Periodically (quarterly or after a cluster of projects)
- When the same pattern appears in multiple project MINDSETs

### Inputs
- All completed project MINDSET.md files
- The "Open Promotions → Global MINDSET" section of each project MINDSET
- Persona MINDSET files (if a pattern has crossed from specialist into general)

### Required Output
Propose updates to Global MINDSET.md. Do NOT modify it directly.

### Proposal Format

## Proposed Global MINDSET Updates

Candidate:
<pattern>

Type:
Heuristic / Anti-pattern / Preference / Risk profile

Reason:
<why this generalizes beyond one project>

Evidence:
- Project: <name> — <1 line>
- Project: <name> — <1 line>

Source:
[self] or [persona-name] — who originated this pattern

Confidence:
Medium / High

---

### Promotion Criteria
Only promote if:
- Appears in ≥2 project MINDSETs
- Not tied to a specific tool, system, or team constraint
- Consistent across different project types
- Represents how decisions are made, not just what was decided
- Still feels true when you imagine a project you haven't done yet

### Rules
- Do NOT modify Global MINDSET.md directly — always propose first
- Keep Global MINDSET ≤100 lines
- No project-specific references in the final Global MINDSET
- Entries must be general enough to apply to any future project
- Remove proposals section after applying accepted candidates

---

## Promotion Flow Summary

```
Project STANCE
    ↓
Project SIGNALS
    ↓
Project MINDSET  ←  distilled at end of project
    ↓  flag in "Open Promotions → Global MINDSET"
Global SIGNALS  ←  staging area for cross-project candidates
    ↓  when pattern appears in ≥2 project MINDSETs
Global MINDSET  (via proposal format, not direct edit)
```

Global files live in:
  0. vibeos-global/global cognitive layer/GLOBAL_SIGNALS.md
  0. vibeos-global/global cognitive layer/GLOBAL_MINDSET.md

Persona MINDSET is a parallel track — specialist craft knowledge that may
occasionally surface a globally applicable pattern. Stage in Global SIGNALS first,
then use the same proposal process to promote to Global MINDSET.
